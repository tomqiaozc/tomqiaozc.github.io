01 · Societas 是什么

它不是文本生成器，而是面向知识工作的通用 Agent。

Societas 面向知识工作者，最初聚焦高质量 Office 成果物，随后扩展到执行并交付完整任务。它把专家经验、工作步骤、工具使用和任务状态组织进同一个 Agent 系统，最终交付可继续编辑和使用的结果。

成果导向

交付完整、可编辑的结果

系统生成文档、演示、数据分析或网页等工作文件，而不只在聊天窗口返回内容片段。

安全执行

在隔离环境和浏览器中工作

代码与文件在隔离环境中处理；需要页面操作时，系统读取当前页面状态并执行多步操作。

能力沉淀

把经验和成功步骤保存下来

领域知识和质量标准保存为技能，成功任务中的稳定步骤保存为工作流，供后续同类任务复用。

02 · 解决什么问题

传统 Copilot 能生成内容，但很难独立完成一项真实工作。

Societas 的核心价值不是让 AI 多写一点内容，而是补齐从回答问题到完成任务之间的三层缺口。

质量缺口

生成内容，不等于专业成果

草稿还需要满足事实、结构、版式和品牌要求，才能成为可以直接使用和继续编辑的工作成果。

复用缺口

回答一次，不等于沉淀能力

团队经验、质量标准和成功步骤需要被保存下来，后续任务才能复用，而不是每次从提示词重新开始。

执行缺口

提出建议，不等于完成任务

真实工作还需要处理文件、调用工具、跨页面获取信息、检查结果，并把最终成果交付给用户。

一句话：让 AI 从一次性回答走向可复用能力，从内容生成走向任务完成。

03 · 演进主线

从成果物创作，扩展到结果达成。

这条演进主线不是“生成更多内容”，而是让系统逐步承担更多完成工作的责任。

1.0

1.0 解决“工作成果应该是什么样”，2.0 解决“这项工作如何被完成”。系统责任从生成专业文件，扩展到明确目标、组织步骤、调用工具、检查结果并完成交付。

04 · TDD 方法论

把专家判断变成可复用的质量标准。

这里的 TDD 指 Taste-Driven Development，不是测试驱动开发。它把品牌、版式、叙事和领域要求写成明确的输入条件与检查标准，使系统不仅追求内容正确，还能判断成果是否专业、是否符合真实使用场景。

输入标准

先定义什么是“好成果”

记录受众、主题、内容目的、交付格式、品牌色和版式要求，用这些条件指导内容组织和视觉表达。

检查与修改

初稿必须经过质量检查

工作流检查事实、结构和视觉效果；发现信息失衡、事实错误或不符合标准时，修改后再交付。

层级关系：TDD 定义成果应该达到什么标准；Skills、Workflows 和 Browser Operator 负责把工作实际完成。

05 · 三类核心能力

三类能力把知识、成功步骤和真实操作沉淀进系统。

I / SKILLS

按需加载领域知识

技能记录专家经验、操作步骤和质量标准；执行相关任务时只加载所需内容，把知识转成 Agent 可以遵循的步骤。

专家经验 → 可执行步骤
II / WORKFLOWS

把成功任务变成可复用流程

系统从成功任务中提取稳定步骤、参数和决策点，经检查后保存为工作流，供后续相似任务参考和执行。

成功任务 → 可复用流程
III / BROWSER OPERATOR

在用户浏览器中完成页面操作

系统读取当前页面状态，并在用户已登录的上下文中执行点击、输入和多步导航；过程保持可见，并由用户控制。

任务意图 → 真实页面操作
06 · Agent Runtime

Agent Runtime 如何执行并恢复一个任务。

Agent Runtime 负责保存任务目标和状态。主 Agent 分解任务并汇总结果，专用 Agent 处理代码、检索等工作；所有工具使用统一接口，代码和文件在隔离环境中处理，任务状态写入持久化存储，以便断线或重启后恢复。

任务控制

个人负责 01 · 结构化工具调用

结构化工具调用：不再解析模型输出的约定文本。

旧方式要求模型生成特定格式的文本，再由 Agent Runtime 解析。结构化工具调用（Native Tool Call）改用模型 SDK（软件开发工具包）提供的标准字段传递工具名称、参数和结果。改造同时覆盖主 Agent、子 Agent、流式消息、结果回填和运行指标，不只是替换文本解析器。

新旧方式并行，按运行指标逐步切换

主 Agent 和子 Agent 使用同一套调用方式，同时保留旧方式作为回退。

个人负责
兼容差异

不同模型 SDK 对工具调用消息、流式事件和结果回填的格式并不一致。

实现方式

模板和 Agent Runtime 可按配置选择结构化调用（Native）或旧文本方式（legacy），主 Agent 与子 Agent 使用相同接口。

迁移依据

运行指标记录所用模式，并按成功率和失败类型决定切换进度，避免一次性替换。

个人负责 02 · 可靠消息传输

Redis List 负责重连重放，Service Bus Session 负责可靠实时投递。

Agent 长任务会持续产生消息片段。旧方案虽然把片段临时保存到 Redis List，但实时链路使用不留存、无确认的 Redis Pub/Sub，后端短暂离线时会漏掉实时消息。我独立抽象传输层并迁移到 Service Bus Session，保留 Redis List 的 24 小时可重放过程态。

Agent 生成片段
Redis List 保存 24h
Service Bus Session 投递
API 确认并推送
重连后 Redis 重放
实时可靠性

队列负责留存、确认、重投和同会话 FIFO

Service Bus Session 在后端暂时不在线时保留未确认消息，并把不同 Agent Run 按 session 隔离和排序。

迁移与回退

新旧传输实现可按配置切换

统一的 MessageTransport 接口允许 Redis 与 Service Bus 分阶段灰度和回退，业务层不随迁移重写。

个人负责 03 · Agent Proxy

把 Agent 封装为可恢复的异步任务接口。

其他产品调用 Agent 时，长任务不能依赖一次同步请求完成。我从 0 设计并交付独立 Agent Proxy：创建持久化任务、提供状态订阅或轮询、返回最终结果，并在代表用户访问下游资源时保持身份和权限边界。

01

创建持久化任务

请求先写入任务存储，不只保存在当前服务进程的内存中。

02

校验用户授权

通过 OBO 认证代表用户访问下游资源，同时保留用户身份和权限边界。

03

重启后恢复状态

服务重启后可找回运行中的任务，并继续返回任务状态。

04

独立部署和发布

容器化和 CI/CD 支持服务独立部署，使外部系统通过稳定接口集成 Agent 能力。

个人负责 · 从 0 设计 / 生产交付 / 服务边界

个人负责 04 · 数据安全与合规

用户级加密保护存储态数据，TLS 保护服务间传输。

我主导用户级加密系统的架构与协议设计，团队据此接入各自数据层；同时独立完成 Societas 后端节点间 HTTP→HTTPS 改造，并为 Agent Proxy 下游链路配置 CA 证书验证，分别覆盖存储态和传输态数据。

从数据库字段到服务间链路，建立两层保护

存储侧支持密钥轮换和渐进迁移，传输侧消除节点间明文通信。

个人负责
用户级加密

通过分层密钥、稳定哈希检索和自描述密文隔离用户数据，并用密钥版本支持轮换。

渐进迁移

系统兼容读取既有明文和新密文，再分批回填，避免一次性停机迁移；团队各模块按统一协议接入自己的数据层。

后端节点间 TLS

把服务间通信从 HTTP 切换到 HTTPS，完成 Key Vault 证书注入、PFX→PEM、服务端证书加载及全环境配置切换。

Proxy 下游 TLS

Agent Proxy 调用后端时使用挂载的 CA 证书验证服务端身份，使内部链路加密并防止连接到伪造服务；该方案为单向 TLS，不表述为 mTLS。
