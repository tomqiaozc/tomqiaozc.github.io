Method · multi-role review

Cross-check from security, architecture, and backend perspectives.

I use Agents in different roles to check security, architecture, and backend issues separately, and arrange an independent Agent to re-check the implementation. A human defines the review scope, produces the minimal reproduction, confirms facts, and submits maintainable patches.

01 / Review scope

Locate high-risk boundaries first

Inspect high-risk locations such as credential storage, tool permissions, persistence, multi-tenant writes, and network egress.

Human-defined focus
02 / Cross-review

Let different Agents check separately

Have different Agents start from different roles and assumptions, and let an Agent not involved in the implementation re-check the results.

Covers different perspectives
03 / Reproducible evidence

Describe the problem and provide tests

Turn each suspicion into problem behavior, impact, a patch, and tests so maintainers can judge and re-check.

Problem → fix → tests

Pairing codes: from plaintext storage to salted hashing

Unconfirmed pairing codes in the local gateway are short-lived credentials; if stored in plaintext, other processes or tools that can read files may obtain them directly.

Adopted after revision
Problem

Unconfirmed pairing codes are stored in plaintext in local state; sandbox or file-reading processes can obtain them directly.

Change

Switched to random salt + SHA-256 storage with constant-time comparison, and migrated existing plaintext records compatibly.

03 · Reliability findings

Persistence failures must be discoverable and recoverable.

Beyond security issues, I also check data safety and persistence consistency on crash, including atomic writes, transaction boundaries, error logging, and concurrency safety. Silently lost data makes long-running Agent tasks unrecoverable.
